# 0006 — Sync local <-> Turso

- **Status:** Draft
- **Phase:** 5
- **Owner:** TBD
- **Depends on:** 0003, 0005

## Problem / why

Local-first data (0003) should follow a signed-in user across devices. We need a simple,
reliable sync between IndexedDB and Turso.

## Goal / outcome

When signed in, loadout profiles, saved calculations, and settings sync between the local
store and Turso. Offline edits reconcile on reconnect using last-write-wins.

## In scope

- Remote storage backend behind the 0003 storage abstraction (server functions).
- TanStack Query for fetching/caching/optimistic updates.
- Sync strategy: **last-write-wins on `updatedAt`**; client-generated UUIDs keep local and
  remote IDs aligned.
- One-time merge on first sign-in (push local, pull remote).

## Out of scope

- Real-time/multi-device live updates, CRDTs, conflict UIs (future).
- Share links (0007).

## Acceptance criteria

- [ ] Signed-in edits on device A appear on device B after sync.
- [ ] Offline edits reconcile on reconnect without data loss (last-write-wins).
- [ ] Anonymous mode still works purely locally.
- [ ] Definition of Done passes.

## Verification

Sign in on two browsers; edit in one; confirm propagation. Test an offline edit then reconnect.
